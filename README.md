## Запуск проекта через Docker

### Компоненты для установки

- Docker Desktop (для Windows и macOS) или Docker Engine и Docker Compose (для Linux).

### Подготовка окружения

1. Скопировать файл `.env.template` в `.env`.
2. Заполнить переменные окружения реальными значениями.

```
cp .env.template .env
```

Для Windows PowerShell:

```powershell
Copy-Item .env.template .env
```

Файл `.env` содержит настройки приложения и секретные данные. Он не должен попадать в Git.

### Сборка и запуск контейнеров

Сборка образов и запуск сервисов:

```
docker compose up -d --build
```

Docker Compose запускает следующие сервисы:

- **web** — Django-приложение с Gunicorn.
- **nginx** — веб-сервер и обратный прокси для Django.
- **redis** — брокер сообщений и хранилище результатов Celery.
- **celery** — обработчик фоновых задач.
- **celery-beat** — планировщик периодических задач.

При запуске контейнера `web` автоматически выполняются миграции базы данных и сбор статических файлов.

### Работа с приложением

Локальный адрес приложения:

http://localhost

Корневой API возвращает ссылки на доступные ресурсы.

### Проверка состояния контейнеров

```
docker compose ps
```

### Просмотр логов

Логи всех сервисов:

```
docker compose logs
```

Просмотр логов в реальном времени:

```
docker compose logs -f
```

Логи конкретного сервиса:

```
docker compose logs -f web
```

### Остановка контейнеров

Остановка контейнеров:

```
docker compose down
```

Команда останавливает и удаляет контейнеры, но сохраняет данные в именованных Docker volumes.

## Развёртывание на сервере

Приложение развёрнуто на виртуальной машине Yandex Cloud под управлением Ubuntu 24.04.

Для запуска используются Docker Compose, Gunicorn и Nginx.

Публичный адрес приложения:

http://153.51.161.214

Nginx принимает HTTP-запросы на порту 80 и перенаправляет их в Django-приложение, работающее через Gunicorn.

Для хранения данных используются Docker volumes.

Контейнеры настроены на автоматический перезапуск после перезагрузки сервера.

## CI/CD — GitHub Actions

Для автоматизации проверки и развёртывания приложения настроен GitHub Actions.

Workflow находится в файле `.github/workflows/ci-cd.yml`.

Pipeline включает следующие этапы:

1. **Tests** — запуск тестов Django.
2. **Lint** — проверка качества кода с помощью Flake8.
3. **Build** — сборка Docker-образа.
4. **Deploy** — автоматическое развёртывание приложения на сервере по SSH.

Развёртывание выполняется после успешного прохождения тестирования, проверки кода и сборки Docker-образа при push в ветку `f9`.

Для подключения к серверу используются GitHub Actions Secrets:
- `SERVER_HOST`
- `SERVER_USER`
- `SERVER_SSH_KEY`

Секретные значения хранятся в настройках репозитория и не передаются в открытом виде в workflow.

При деплое сервер получает последние изменения из репозитория и пересобирает и перезапускает Docker-сервисы.
